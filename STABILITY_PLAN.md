# План стабилизации стенда SPG-023MK

Отправная точка (2026-10-15). Шаги корректируются и вычёркиваются по ходу работы.
Подробности по коду и логам — в README, «Известные проблемы и TODO».

## Жалобы

1. Перебег НМТ при доводке после испытания (рывком, на случайное расстояние).
2. Ложные аварии: на высокой скорости срабатывает верхнее аварийное положение
   траверсы, хотя траверса не двигалась (помеха).
3. Реже — неверные результаты (шум или ошибки расчёта) — разбирать после 0–3.

## Почему так (по коду и логам, не всё подтверждено на стенде)

Ошибаются три звена подряд: **чтение буфера → определение движения шатуна →
остановка/доводка**. Пока первые два дают неверные данные, доводку чинить
бесполезно (попытки 12.10 и 13.10 сделали хуже).

- **Буфер.** На каждом этапе буфер выключается и включается, чтение начинается с
  0x4000 и первая прочитанная запись принимается без проверки. В логе 15.10
  скачки положения (`-35.5 -> 60.9`, `-17.6 -> 3.0`, `-4.7 -> 41.3`) ровно через
  13–14 мс после начала этапа (≈ 40 записей, ≈ 70 мс после подтверждения
  `buffer_on`) — похоже, первые записи от прошлой сессии: обнуление буфера
  контроллером не успевает или идёт позже подтверждения записи.
  Номера записей прошлой короткой сессии (< 3000 записей) совпадают с новыми —
  по номеру старые не отличить.
- **Остановка привода** (`StopDetector`, `CycleCollector._update_threshold`):
  порог = 3 × скорость за последние 7 мс, при плавном движении шток всегда
  «ниже порога». «Стоп» срабатывает через 0.5 с данных без разворота, даже на
  ходу. `STOP_GEAR_END_TEST` короче 0.6 с — в 473 из 1589 случаев по логам.
  Доводка подаёт «вперёд» на ещё крутящийся шатун.
- **Доводка** работает поверх двух неверных сигналов, отсюда случайный перебег.

## Шаги

### 1. Достоверное чтение буфера (фундамент)
- чтение — только после подтверждённого `buffer_on` (+ пауза, если покажет шаг 0);
- первая запись в 0x4000 должна быть №1;
- номер записи = время контроллера в мс: запись N не может появиться заметно
  раньше N мс от начала сессии — иначе она старая;
- разрыв данных (переполнение кольца, сбой) — явное событие для коллектора, а не
  склеенный поток; отставание видно по номеру записи;
- решить по данным шага 0: перезапуск буфера на каждом этапе или буфер включён
  всё испытание (плюс периодическое чтение регистров ради траверсы/концевиков).

### 2. Новое определение движения шатуна
Отдельный модуль вместо логики в `CycleCollector`:
- скорость по фиксированному окну по времени контроллера (номер записи);
- развороты по положению с гистерезисом (отход от экстремума на 1–2 мм);
- «стоп» = скорость ниже фиксированного порога **и** разброс положения < 0.3 мм
  в течение 0.3 с;
- НМТ/ВМТ по настоящим разворотам.
Отлаживается на записях шага 0.

### 3. Доводка до НМТ — простой алгоритм
стоп → ждать настоящей остановки (сколько бы ни длился выбег) → если в НМТ ±
допуск — готово, привод не запускать → иначе медленно вперёд и стоп с
упреждением → в лог, где остановился.

### 4. Быстрые исправления безопасности — сделано 2026-10-15
- [x] Запись регистров (`WriterThread`, 'reg'): при исключении pymodbus (нет ответа)
  попытка не считалась — бесконечный цикл, очередь команд (в т.ч. «стоп»)
  вставала навсегда.
- [x] Окно «Ход шатуна равен…» открывалось внутри такта контроллера: пока оно
  открыто, таймер контроллера не срабатывал (Qt не вызывает таймер повторно) —
  не проверялись аварии и страховка буфера.
- [x] Траверса останавливалась только в ±0.3 мм от цели; если проскочила — ехала
  дальше до концевика. Теперь проезд цели тоже останавливает её, после остановки
  (положение стоит 0.5 с) она возвращается к цели на малой скорости — не больше
  2 возвратов, дальше положение принимается как есть. Всё — WARNING в логе
  (`Траверса проехала цель`, `возврат к цели`, `не вернулась в цель`).
- [x] Помеха концевика траверсы на высокой скорости: фильтр по числу чтений
  (3 чтения ≈ 10–15 мс) дополнен фильтром по времени `ALARM_FILTER_MS`.
  Если помеха останется — следующий шаг: проверка правдоподобия
  (траверса стоит и далеко от верха — концевик сработать не мог).
