1. ЧТО ДЕЛАЕТ ПРОГРАММА
--------------------------------------------------------------------------
Настольное приложение Windows (Python 3.11, PySide6/Qt, графики pyqtgraph)
для управления стендом испытания амортизаторов.

Механика стенда:
  - амортизатор зажимается между траверсой (подвижная каретка, выставляется
    по длине амортизатора) и шатуном кривошипного механизма;
  - шатун крутит приводной двигатель (частотный преобразователь, ЧП №1),
    траверсу двигает свой двигатель (ЧП №2); ЧП — Evra или Delta;
  - датчики: усилие на штоке, перемещение штока (инкрементная линейка),
    положение траверсы, две температуры, концевики, ограждение,
    механическая «жёлтая» кнопка SB3.

Программа общается только с контроллером стенда (Modbus RTU по COM-порту,
460800 бод). Контроллер:
  - отдаёт текущие значения датчиков в регистрах;
  - во время испытания пишет осциллограмму (запись каждую 1 мс) в кольцевой
    буфер, программа вычитывает её пачками;
  - ретранслирует программе команды на ЧП (программа кладёт готовый
    Modbus-кадр для ЧП в «почтовый ящик» контроллера).

Программа: ведёт испытание по шагам (траверса, разгон, сбор циклов на
заданных скоростях, остановка в НМТ), считает результаты (усилия отбоя/
сжатия, мощность, частоту), рисует графики и пишет архив в CSV.

4. ОБМЕН С КОНТРОЛЛЕРОМ (MODBUS)
--------------------------------------------------------------------------
Карта регистров — scripts/modbus/registers.py, описание контроллера —
doc/«Стенд СПГ-005МК -команды управления ModBus.doc».

4.1 Чтение (my_thread/thread_reader.py, ReaderThread — фоновый поток)
  Два режима:
  а) 'reg' — непрерывно читается блок 0x2000..0x200D (14 регистров):
       0x2000-01  усилие (float, старшее слово первым)
       0x2002     перемещение штока (знаковое, ×0.1 мм; в коде ×(-0.1))
       0x2003     слово состояния (биты: 0 буфер вкл, 1/2 красная/зелёная
                  лампа, 3 потеря управления, 4 превышение усилия,
                  6 канал температуры, 8 ограждение, 11 ЧП занят,
                  12 датчик силы занят, 13 жёлтая кнопка)
       0x2004     счётчик времени (1 мс)
       0x2005     входы модуля МВ110 (концевики траверсы и её блокировки)
       0x2006     положение траверсы (×(-0.05) мм)
       0x2007-08  температура 1 (float)
       0x200A-0B  аварийное усилие (float)
       0x200C-0D  температура 2 (float)
  б) 'buffer' — во время испытания читается кольцевой буфер с 0x4000:
       3000 записей по 6 регистров: [номер записи, усилие ст., усилие мл.,
       перемещение, слово состояния, температура ×100]. Пачка — 20 записей.
       Поток проверяет непрерывность по номеру записи (предыдущий + 1) и
       сам переходит по кольцу.
  Результат чтения отдаётся сигналом Qt в главный поток:
  Reader (scripts/reader.py) -> Model._reader_result.

4.2 Запись (writer.py + my_thread/thread_writer.py)
  Writer держит очередь команд, по таймеру отдаёт по одной в WriterThread:
  - 'reg': запись регистров (write_registers), до 5 попыток.
    Слово состояния 0x2003 пишется целиком: Model._write_reg_state собирает
    его из прочитанного состояния, а биты, которыми управляет программа
    (буфер, лампы), берёт из последней отправленной команды
    (Model.commanded_bits) — иначе соседние команды затирали друг друга.
  - 'FC': команда на ЧП через «почтовый ящик» контроллера:
      ждать бит 11 (ЧП свободен) -> записать длину 8 в 0x2060 ->
      ждать -> записать кадр в 0x2061..
  Результат записи — сигнал Writer.check_buffer (для команд буфера) и лог.

4.3 Команды ЧП (freq_ctrl/freq_control.py)
  FreqControl.freq_command(tag, adr, speed/freq, hod) собирает Modbus-RTU кадр
  для ЧП: "0{адрес ЧП}" + команда + значение + CRC16 (crcmod), и режет его
  на регистры. Команды: up/down/stop (пуск вперёд/назад/стоп), speed
  (частота), max. Коды команд разные для Evra и Delta (FREQ в .env).
  Частота из скорости испытания: _freq_from_speed:
      f(Гц ×100) = коэф × v / r,  коэф = 2·17.99 / (2π·0.98)
      (17.99 — редуктор, 0.98 — скольжение, r = ход/2).
  Адрес 1 — привод шатуна, адрес 2 — траверса.

4.4 Буфер включается/выключается битом 0 слова 0x2003
  (Model.write_bit_force_cycle). Переход между этапами с включением буфера —
  Model.transition_via_buffer -> этап WAIT_BUFFER: он ждёт подтверждения
  записи команды buffer_on и только тогда начинает читать буфер с 0x4000.
  Страховка: нет данных из буфера BUFFER_TIMEOUT с — перезапуск буфера,
  после BUFFER_RESTARTS попыток — авария со стопом привода
  (Controller._check_buffer_watchdog).

6. ХОД ИСПЫТАНИЯ (controller/controller.py)
--------------------------------------------------------------------------
Controller — конечный автомат. Таймер вызывает обработчик текущего этапа
(_stage_*), есть обработчики входа/выхода (_enter_*/_exit_*).

Виды испытаний (TypeTest): LAB (две скорости), LAB_HAND (ручная скорость),
LAB_CASCADE (набор скоростей), CONV (конвейерное: две скорости + лампы
годен/брак), TEMPER (до заданной температуры), SETTINGS (окно отладки).

Типичный путь:
  start_test_clicked -> траверса в точку установки (INSTALL_AMORT) ->
  сообщение «нажмите ЗАПУСК или жёлтую кнопку» -> START_POINT_AMORT
  (траверса в точку испытания) -> TEST_MOVE_CYCLE (медленные обороты,
  поиск НМТ/ВМТ) -> PUMPING (прокачка) -> этапы скоростей
  (TEST_SPEED_ONE/TWO, TEST_LAB_CASCADE, TEST_LAB_HAND_SPEED, TEST_TEMPER)
  -> STOP_GEAR_END_TEST (стоп, ждём остановки) -> STOP_GEAR_MIN_POS
  (медленно до НМТ) -> WAIT. «НАЗАД» -> STOP_TEST (траверса в точку снятия).
  Отдельные функции: SEARCH_HOD (определение хода), POS_SET_GEAR
  (настройка хода: остановка шатуна в середине обратного хода),
  ALARM_TRAVERSE (уход траверсы с аварийного концевика).

Аварии (controller/alarm_steps.py): потеря управления, превышение усилия,
ограждение, перегрев, концевики траверсы. Концевики, ограждение и перегрев
фильтруются от помех (ALARM_FILTER_READS чтений подряд). Авария
останавливает приводы, закрывает запись в архиве, включает красную лампу.

Жёлтая кнопка (scripts/yellow_button.py + AppWindow.yellow_btn_pressed):
нажатие = активная экранная кнопка (ЗАПУСК / ПРЕРВАТЬ / НАЗАД).


7. СБОР ЦИКЛОВ (controller/cycle_collector.py)
--------------------------------------------------------------------------
CycleCollector получает поток (перемещение, усилие) из буфера, считает
скорость по окну точек, определяет развороты штока (смена знака скорости),
НМТ/ВМТ, обороты, и выполняет «программу» шагов (load_program):
  DETECT_ONLY — пропустить N оборотов (разгон; ждёт, пока фактическая
                скорость π·ход/период не наберётся до SPEED_TOLERANCE)
  COLLECT     — собрать N оборотов (данные испытания)
  STROKE_ONLY — определение хода (мин/макс за оборот)
  WAIT_STOP   — ждать остановки привода
  NMT_FINAL   — довести до НМТ
  MID_FINAL   — остановка в середине обратного хода (с упреждением MID_LEAD)
Скачок координаты > 5 мм за запись (линейка после включения стенда прошла
референтную точку) сбрасывает отслеживание — накопленное до скачка в
старых координатах.
По окончании шага Model._handle_program_done забирает результат.


8. РАСЧЁТ ВЕЛИЧИН (Model + data_calculation.py)
--------------------------------------------------------------------------
Для собранного оборота (Model._pars_result_avarage_cycles и далее):
  - перемещение сдвигается так, что НМТ = 0 (CalcData.move_from_nmt);
  - знак усилия переворачивается (отбой +, сжатие −);
  - усилие × FORCE_KOEF + ноль датчика (force_koef_offset, задаётся
    обнулением датчика в окне отладки);
  - отбой/сжатие = |max/min усилия + выталкивающая сила|
    (статическая — вводится оператором, или динамическая —
    calc_dynamic_push_force_array: по усилию в НМТ и ВМТ);
  - «мощность» — calc_power_amort_array: работа за цикл ∑|Δx|·|F|
    (кгс·мм × 0.009807 / 1000 = кДж);
  - частота качания f = v / (π·ход) — calc_freq_piston_amort;
  - контроль скорости: фактическая = π · ход / период оборота.
Температурное испытание: те же расчёты на каждом обороте, точки
(температура, отбой, сжатие) копятся в DataTest, максимум температуры —
по медиане трёх последних чтений.
Конвейерное: result_conveyor_test сравнивает отбой/сжатие с допусками
амортизатора, включает зелёную/красную лампу (итог по обеим скоростям).

10. АРХИВ (archive/ГГГГ-ММ-ДД.csv)
--------------------------------------------------------------------------
Запись — scripts/archive_saver.py (WriterArch, свой фоновый поток с очередью):
  - кодировка Windows-1251 (Excel на стенде иначе не читает), разделитель ;,
    десятичная запятая;
  - одна запись = 2 строки: шапка (время, оператор, тип, амортизатор,
    серийник, параметры и допуски амортизатора, выталкивающая сила,
    макс. температура, скорость; 24 колонки) + первый график (перемещение
    или температура), затем строка «*;;;…» + второй график (усилие или
    «отбой|сжатие» для температурного);
  - испытание закрывается строкой end_test; шаги каскада и скорости
    лабораторного/конвейерного — отдельные записи;
  - если файл открыт в Excel — запись ждёт и просит закрыть файл;
  - при старте нового испытания незакрытое предыдущее закрывается.
Чтение — scripts/archive.py (ReadArchive): разбирает файл в pydantic-схемы
LabSchema/ConvSchema/TempSchema/CascSchema, понимает старые имена файлов
(ДД.ММ.ГГГГ.csv) и кодировку UTF-8. Окно — app/wins/archive_win.py.
Правила ручной правки архива в Excel — README, раздел «Архив и логи».

12. РАБОТА БЕЗ СТЕНДА
--------------------------------------------------------------------------
Эмулятор Modbus Slave (проекты в MBSlave/) + пара виртуальных COM-портов
com0com; в .env — второй порт пары и TIMEOUT = 0.1. Подробно — README,
