1. ЧТО ДЕЛАЕТ ПРОГРАММА
--------------------------------------------------------------------------
Десктопное приложение Windows (Python 3.11, PySide6/Qt, графики pyqtgraph)
для управления стендом испытания амортизаторов.

Механика стенда:
  - амортизатор зажимается между траверсой (подвижная каретка, выставляется
    по длине амортизатора) и шатуном кривошипного механизма;
  - шатун крутит приводной двигатель (частотный преобразователь, ЧП №1),
    траверсу двигает свой двигатель (ЧП №2);
  - датчики: усилие на штоке, перемещение штока (инкрементная линейка),
    положение траверсы, две температуры, концевики, ограждение,
    механическая «жёлтая» кнопка SB3.

Программа общается только с контроллером стенда (Modbus RTU по COM-порту,
460800 бод). Контроллер:
  - отдаёт текущие значения датчиков в регистрах;
  - во время вращения пишет осциллограмму (запись каждую 1 мс) в кольцевой
    буфер, программа вычитывает её пачками;
  - ретранслирует команды на ЧП (программа кладёт готовый Modbus-кадр для ЧП
    в регистры контроллера).

Программа ведёт испытание по этапам (траверса, разгон, сбор оборотов на
заданных скоростях, остановка в НМТ), считает результаты (усилия отбоя/
сжатия, мощность, частоту), рисует графики и пишет архив в CSV.

4. ОБМЕН С КОНТРОЛЛЕРОМ (MODBUS)
--------------------------------------------------------------------------
Карта регистров — scripts/modbus/registers.py, описание контроллера —
doc/«Стенд СПГ-005МК -команды управления ModBus.doc».

4.1 Чтение (my_thread/thread_reader.py, ReaderThread — фоновый поток)
  а) 'reg' — непрерывно читается блок 0x2000..0x200D (14 регистров):
       0x2000-01  усилие (float, старшее слово первым)
       0x2002     перемещение штока (знаковое, ×0.1 мм; в коде ×(-0.1))
       0x2003     слово состояния (биты: 0 буфер вкл, 1/2 красная/зелёная
                  лампа, 3 потеря управления, 4 превышение усилия,
                  6 канал температуры, 8 ограждение, 9 блокировка траверсы,
                  11 ЧП занят, 12 датчик силы занят, 13 жёлтая кнопка)
       0x2004     счётчик времени (1 мс)
       0x2005     входы модуля МВ110 (концевики траверсы и её блокировки)
       0x2006     положение траверсы (×(-0.05) мм)
       0x2007-08  температура 1 (float)
       0x200A-0B  аварийное усилие (float)
       0x200C-0D  температура 2 (float)
  б) 'buffer' — во время вращения читается кольцевой буфер с 0x4000:
       3000 записей по 6 регистров: [номер записи, усилие ст., усилие мл.,
       перемещение, слово состояния, температура ×100]. Пачка — 20 записей.
       Каждая сессия буфера начинается с записи №1; поток проверяет
       непрерывность по номеру записи и сам переходит по кольцу.
  Каждая сессия чтения буфера имеет номер, результаты прошлой сессии
  отбрасываются (Model._pars_buffer_result).

4.2 Запись (writer.py + my_thread/thread_writer.py)
  Writer держит очередь команд, по таймеру отдаёт по одной в WriterThread:
  - 'reg': запись регистров, до 5 попыток. Слово состояния 0x2003 пишется
    целиком: биты буфера и ламп — из последней отправленной команды
    (Model.commanded_bits), остальные — из прочитанного состояния;
  - 'FC': команда на ЧП: ждать бит 11 (ЧП свободен) -> длина команды = 8 в
    0x2060 -> ждать -> кадр в 0x2061..
  Результат записи команд буфера — сигнал Writer.check_buffer.

4.3 Команды ЧП (freq_ctrl/freq_control.py)
  FreqControl.freq_command(tag, adr, speed/freq, hod) собирает Modbus-RTU кадр
  для ЧП (адрес, команда, значение, CRC16). Команды: up/down/stop, speed, max.
  Коды команд разные для Evra и Delta (FREQ в .env).
  Частота из скорости испытания (_freq_from_speed):
      f = 2·17.99·v / (2π · SPEED_SLIP · r) − SPEED_FREQ_OFFSET_HZ
      (17.99 — редуктор, r = ход/2).
  Адрес 1 — привод шатуна, адрес 2 — траверса.

4.4 Буфер включается/выключается битом 0 слова 0x2003
  (Model.write_bit_force_cycle). Переход между этапами с вращением —
  Model.transition_via_buffer -> этап WAIT_BUFFER: ждёт подтверждения
  записи команды buffer_on и только тогда начинает читать буфер.
  Страховка: нет данных BUFFER_TIMEOUT (с) — перезапуск буфера,
  после BUFFER_RESTARTS попыток — авария со стопом привода
  (Controller._check_buffer_watchdog).

6. ХОД ИСПЫТАНИЯ (controller/controller.py)
--------------------------------------------------------------------------
Controller — конечный автомат. Таймер (100 мс) вызывает обработчик текущего
этапа (_stage_*), есть обработчики входа/выхода (_enter_*/_exit_*).

Виды испытаний (TypeTest): LAB (две скорости), LAB_HAND (ручная скорость),
LAB_CASCADE (набор скоростей), CONV (конвейерное: две скорости + лампы
годен/брак), TEMPER (до заданной температуры), SETTINGS (окно отладки).

Типичный путь:
  траверса в точку установки (INSTALL_AMORT, при неизвестной референтной
  точке — сначала TRAVERSE_REFERENT) -> «нажмите ЗАПУСК или жёлтую кнопку» ->
  START_POINT_AMORT (траверса в точку испытания) -> TEST_MOVE_CYCLE
  (медленные обороты, НМТ/ВМТ) -> PUMPING (прокачка) -> этапы скоростей
  (TEST_SPEED_ONE/TWO, TEST_LAB_CASCADE, TEST_LAB_HAND_SPEED, TEST_TEMPER)
  -> STOP_GEAR_END_TEST (стоп, ждём конца торможения) -> STOP_GEAR_MIN_POS
  (медленно до НМТ) -> WAIT. «НАЗАД» -> STOP_TEST (траверса в точку снятия).
  Отдельные функции: SEARCH_HOD (определение хода), POS_SET_GEAR
  (настройка хода: остановка шатуна в середине обратного хода),
  ALARM_TRAVERSE (уход траверсы с аварийного концевика).

Траверса (traverse_service.py): замедление по мере приближения, стоп в
±0.3 мм от цели; проехала цель — стоп и возврат к цели (до 2 раз).

Аварии (controller/alarm_steps.py): потеря управления, превышение усилия,
ограждение, перегрев, концевики траверсы, нет данных буфера. Концевики,
ограждение и перегрев фильтруются от помех по длительности сигнала.
Авария останавливает приводы, закрывает запись в архиве, включает красную лампу.

Жёлтая кнопка (scripts/yellow_button.py + AppWindow.yellow_btn_pressed):
нажатие = активная экранная кнопка (ЗАПУСК / ПРЕРВАТЬ / НАЗАД).


7. СБОР ОБОРОТОВ (controller/cycle_collector.py)
--------------------------------------------------------------------------
CycleCollector получает поток (перемещение, усилие) из буфера и выполняет
«программу» шагов (load_program):
  DETECT_ONLY — пропустить N оборотов (разгон; ждёт, пока фактическая
                скорость π·ход/период не наберётся до SPEED_TOLERANCE)
  COLLECT     — собрать обороты результата: шаг заканчивается, когда
                COLLECT_STABLE_CYCLES оборотов подряд совпали по отбою и
                сжатию (COLLECT_STABLE_PCT); не совпали за COLLECT_MAX_CYCLES —
                в результат оборот с наибольшим усилием
  STROKE_ONLY — определение хода (мин/макс за оборот)
  WAIT_STOP   — ждать конца торможения: положение за STOP_WINDOW_MS
                сдвинулось не больше STOP_SPAN_MM
  NMT_FINAL   — довести до НМТ
  MID_FINAL   — остановка в середине обратного хода (с упреждением MID_LEAD)
Развороты — по положению с гистерезисом TURN_HYST_MM (отход от экстремума),
оборот — НМТ->ВМТ->НМТ. Скачок координаты > 5 мм за запись (линейка после
включения стенда прошла референтную точку) сбрасывает отслеживание.
По окончании шага Model._handle_program_done забирает результат.


8. РАСЧЁТ ВЕЛИЧИН (Model + data_calculation.py)
--------------------------------------------------------------------------
Для собранного оборота:
  - перемещение сдвигается так, что НМТ = 0;
  - знак усилия переворачивается (отбой +, сжатие −);
  - усилие × FORCE_KOEF + ноль датчика (обнуление в окне отладки и при
    поиске референтной точки);
  - отбой/сжатие = |max/min усилия + выталкивающая сила|
    (статическая — вводится оператором, или динамическая — по усилию в НМТ и ВМТ);
  - «мощность» — работа за оборот ∑|Δx|·|F| (кДж);
  - частота качания f = v / (π·ход);
  - контроль скорости: фактическая = π · ход / период оборота (в лог).
Температурное испытание: те же расчёты на каждом обороте, точки
(температура, отбой, сжатие) копятся в DataTest, максимум температуры —
по медиане трёх последних чтений.
Конвейерное: result_conveyor_test сравнивает отбой/сжатие с допусками
амортизатора, включает зелёную/красную лампу (итог по обеим скоростям).

10. АРХИВ (archive/ГГГГ-ММ-ДД.csv)
--------------------------------------------------------------------------
Запись — scripts/archive_saver.py (WriterArch, фоновый поток с очередью):
  - кодировка Windows-1251, разделитель ;, десятичная запятая (Excel);
  - одна запись = 2 строки: шапка (24 колонки) + первая координата
    (перемещение или температура), затем строка «*;;;…» + вторая координата
    (усилие или «отбой|сжатие» для температурного);
  - испытание закрывается строкой end_test; каждая скорость и каждый шаг
    каскада — отдельная запись;
  - если файл открыт в Excel — запись ждёт и просит закрыть файл.
Чтение — scripts/archive.py (ReadArchive) в pydantic-схемы
LabSchema/ConvSchema/TempSchema/CascSchema. Окно — app/wins/archive_win.py.


11. ЛОГИ И ДИАГНОСТИКА
--------------------------------------------------------------------------
logs/ГГГГ-ММ-ДД.log — уровень LOG_LEVEL (10 = DEBUG: переходы этапов,
команды ЧП, записи регистров). INFO: скорость каждого шага, время торможения
шатуна, совпадение оборотов; WARNING: помехи аварий, нестабильные обороты,
проезд цели траверсой, страховка буфера.
BUFFER_DUMP = 1 — запись сырого потока буфера и событий обмена в
logs/buffer/ГГГГ-ММ-ДД/, разбор — tools/buffer_dump (README, «Логи и диагностика»).


12. РАБОТА БЕЗ СТЕНДА
--------------------------------------------------------------------------
Эмулятор Modbus Slave (проекты в MBSlave/) + пара виртуальных COM-портов
com0com; в .env — второй порт пары и TIMEOUT = 0.1.
