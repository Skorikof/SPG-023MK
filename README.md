# SPG-023MK — ПО управления испытательным стендом амортизаторов

Настольное приложение (Windows, Python 3.11, PySide6, графики pyqtgraph) для
управления испытательным стендом амортизаторов SPG-023MK: позиционирование
траверсы, вращение шатуна через частотные преобразователи, чтение усилия,
перемещения и температуры по Modbus, расчёт результатов, графики и архив.

Краткий обзор «что где лежит» — `doc/Устройство программы SPG-023MK.txt`,
протокол контроллера — `doc/Стенд СПГ-005МК -команды управления ModBus.doc`.

## Стенд

Амортизатор зажимается между траверсой (подвижная каретка, выставляется по
длине амортизатора) и шатуном кривошипного механизма. Привод крутит шатун с
заданной скоростью, стенд меряет усилие на штоке, перемещение штока
(инкрементная линейка) и температуру; по одному обороту строится график
усилие/перемещение и производные от него.

Программа общается только с контроллером стенда (Modbus RTU, COM-порт,
460800 бод). Контроллер отдаёт текущие значения датчиков в регистрах, во время
испытания пишет осциллограмму (запись каждую 1 мс) в кольцевой буфер и
ретранслирует команды на два частотных преобразователя (ЧП «Evra» или «Delta»):
- адрес 1 — привод шатуна;
- адрес 2 — привод траверсы.

Линейка штока после включения стенда считает от нуля и при прохождении
референтной точки переходит в абсолютные координаты (скачок показаний), шум
линейки ±0.1 мм. Линейка траверсы перевёрнута: верх — меньшие значения.
Аварийные концевики траверсы: верхний — около −12 мм, нижний — после ≈ 550 мм;
сработавший концевик механически блокирует траверсу, вывести её можно только
командой из программы вместе с кнопкой на корпусе стенда.

## Архитектура

```
main.py
 └─ AppWindow (app/wins/view.py)       — главное окно, графики, кнопки
     ├─ Model (scripts/model.py)       — состояние стенда, данные испытания,
     │                                    разбор ответов, запись команд, расчёты
     ├─ Controller (scripts/controller/controller.py)
     │                                  — конечный автомат испытания (Stage)
     │   ├─ AlarmSteps                 — обработка аварий
     │   └─ TraverseService            — позиционирование траверсы
     └─ дочерние окна (архив, амортизаторы, операторы, настройки)

Model
 ├─ Client (scripts/modbus/client.py)          — pymodbus RTU-клиент, COM-порт
 ├─ Reader (scripts/reader.py)                 → ReaderThread (my_thread/thread_reader.py)
 ├─ Writer (scripts/writer.py)                 → WriterThread (my_thread/thread_writer.py)
 ├─ WriterArch (scripts/archive_saver.py)      — запись архива (свой фоновый поток)
 ├─ ParserSPG023MK (scripts/parser/parser.py)  — регистры → физические величины
 ├─ CalcData (scripts/data_calculation.py)     — математика испытаний
 ├─ FreqControl (scripts/freq_ctrl/freq_control.py) — кадры команд для ЧП
 └─ CycleCollector (scripts/controller/cycle_collector.py)
                                               — обороты, развороты, НМТ/ВМТ, остановка
```

`Reader`/`Writer` — диспетчеры в главном Qt-потоке; обмен с портом идёт в
фоновых `QRunnable` (`ReaderThread`, `WriterThread`), результаты возвращаются
Qt-сигналами. Команды записи выполняются строго по одной из очереди
(`Writer.list_write`, таймер 50 мс).

## Поток данных

1. `ReaderThread` непрерывно читает 14 регистров с `0x2000` (режим `'reg'`).
2. На этапах с вращением программа включает буфер контроллера (бит 0 слова
   `0x2003`), ждёт подтверждения записи команды `buffer_on` (этап
   `WAIT_BUFFER`) и переключает чтение в режим `'buffer'`: кольцевой буфер с
   `0x4000`, по 20 записей × 6 регистров за раз, с проверкой непрерывности по
   номеру записи (после 65535 нумерация продолжается с 1). Каждая сессия
   буфера начинается с записи №1 в начале буфера.
3. Каждая сессия чтения буфера получает номер (`Model.buffer_session`);
   результаты прошлой сессии, ещё стоящие в очереди Qt-сигналов, отбрасываются,
   а `CycleCollector` в начале сессии начинает отслеживание движения заново
   (`on_stream_restart`), сохраняя программу сбора и известные НМТ/ВМТ.
4. `Model._reader_result` разбирает ответ (`ParserSPG023MK`), обновляет
   состояние (`state_dict`, `switch_dict`, температуры, аварии, жёлтая кнопка)
   и в режиме буфера передаёт поток точек в `CycleCollector`.
5. По завершении шага программы коллектора `Model` считает результат и шлёт
   сигнал на обновление окна; после каждой скорости запись уходит в архив.
6. Команды (ЧП, лампы, буфер, аварийное усилие) идут через
   `Model` → `Writer.write_out()` → очередь → `WriterThread` → Modbus.
   Запись регистра — до 5 попыток; команда ЧП — ожидание свободного ЧП (бит 11),
   длина кадра в `0x2060`, кадр в `0x2061`.

Страховка буфера (`Controller._check_buffer_watchdog`): нет данных
`BUFFER_TIMEOUT` секунд или не подтверждается `buffer_on` — буфер
перезапускается с возвратом на тот же этап; после `BUFFER_RESTARTS`
перезапусков подряд — авария «нет данных от контроллера» со стопом привода.

## Виды испытаний

`TypeTest` (`scripts/controller/stages.py`):

| Тип | Что делает |
|---|---|
| `LAB` | Лабораторное: две паспортные скорости амортизатора (`speed_one`, `speed_two`) |
| `LAB_HAND` | Одна скорость, заданная оператором; после испытания скорость можно сменить и повторить |
| `LAB_CASCADE` | Каскад: последовательный прогон по списку скоростей (до 30, строго по возрастанию) |
| `CONV` | Конвейерное (приёмочное): две скорости, сравнение с допусками, зелёная/красная лампа — общий итог |
| `TEMPER` | Температурное: непрерывное вращение до целевой температуры, накопление точек отбой/сжатие от температуры |
| `SETTINGS` | Окно ручной отладки: прямое управление стендом, просмотр регистров и буфера, обнуление датчика усилия |

Дополнительные функции главного окна:
- **Определение хода** (`SEARCH_HOD`) — обороты на быстрой скорости, ход по
  минимуму/максимуму положения, затем доводка до НМТ;
- **Настройка хода** (`POS_SET_GEAR`) — остановка шатуна в середине обратного
  хода (ВМТ→НМТ), где доступны регулировочные гайки;
- **Обнуление датчика усилия** и сброс обнуления.

## Ход испытания

`Controller` — табличный конечный автомат (`Stage` → обработчики
enter/stage/exit), такт — таймер 100 мс.

```
WAIT
 → TRAVERSE_REFERENT   поиск референтной точки траверсы (если она неизвестна),
                        обнуление датчика усилия
 → INSTALL_AMORT       траверса в точку установки; ожидание «ЗАПУСК» / жёлтой кнопки
 → START_POINT_AMORT   траверса в точку испытания
 → TEST_MOVE_CYCLE     медленные обороты, определение НМТ/ВМТ
 → PUMPING             прокачка на быстрой скорости
 → TEST_SPEED_ONE → TEST_SPEED_TWO   (или TEST_LAB_HAND_SPEED / TEST_LAB_CASCADE /
                                       TEST_TEMPER — по виду испытания)
 → STOP_GEAR_END_TEST  «стоп» привода, ожидание конца торможения
 → STOP_GEAR_MIN_POS   медленно до НМТ, «стоп» в НМТ
 → WAIT                «НАЗАД» → STOP_TEST (траверса в точку снятия)
```

Переходы между этапами с вращением идут через `WAIT_BUFFER`
(`Model.transition_via_buffer`): команда скорости и пуска на ЧП, `buffer_on`,
ожидание подтверждения, затем чтение буфера и следующий этап.

**Скорость.** Частота ЧП из скорости испытания (`FreqControl._freq_from_speed`):
`f = 2 · 17.99 · v / (2π · SPEED_SLIP · r) − SPEED_FREQ_OFFSET_HZ`, где 17.99 —
передаточное число редуктора, r — половина хода. Медленная / быстрая
скорость служебных этапов — по ходу (`CalcData.SPEED_CONFIG`: до 100 мм —
0.02 / 0.1 м/с, больше 100 мм — 0.03 / 0.2 м/с). Допустимые скорости испытания
— от 0.02 до `CalcData.max_speed(ход)` (предел частоты ЧП).

**Траверса** (`TraverseService`): частота 30 / 15 / 5 Гц по мере приближения,
«стоп» в пределах ±0.3 мм от цели. Если траверса проехала цель, она
останавливается и после остановки возвращается к цели на малой скорости (не
больше 2 возвратов, дальше положение принимается как есть).

**Остановка шатуна** (`StopDetector`): привод закончил торможение, если за
последние `STOP_WINDOW_MS` записей буфера положение сдвинулось не больше чем на
`STOP_SPAN_MM`. Полной неподвижности не требуется: после торможения шатун
может долго ползти под действием амортизатора. Не остановился за
`STOP_TIMEOUT` — команда «стоп» повторяется.

**Доводка до НМТ** (`Mode.NMT_FINAL`): на медленной скорости, «стоп», когда
положение в пределах 1 мм от НМТ, известной по оборотам испытания.

**Настройка хода** (`Mode.MID_FINAL`): точка остановки считается на развороте
в ВМТ как `(НМТ + ВМТ) / 2 + MID_LEAD`, если подъём начался из настоящей НМТ
(перед этим был разворот после спуска ≥ 10 мм или старт совпал с известной
НМТ ± 2 мм); иначе ВМТ пропускается — шатун делает лишний оборот. «Стоп» — при
пересечении точки на спуске. Где шатун фактически встал — DEBUG в логе.

## Сбор оборотов

`CycleCollector` получает поток (перемещение, усилие) и выполняет программу
шагов (`load_program`):

| Режим | Что делает |
|---|---|
| `DETECT_ONLY` | пропустить N оборотов; с заданной скоростью — ждать, пока фактическая скорость (π · ход / период оборота) не окажется не ниже заданной больше чем на `SPEED_TOLERANCE` два оборота подряд, не дольше `SPEED_WAIT_CYCLES` оборотов |
| `COLLECT` | собрать обороты результата (испытание); без числа — бесконечно, каждый оборот в обработчик (температурное) |
| `STROKE_ONLY` | определение хода |
| `WAIT_STOP` | ждать конца торможения |
| `NMT_FINAL` | доводка до НМТ |
| `MID_FINAL` | остановка в середине обратного хода |

**Развороты** определяются по положению: разворот засчитывается, когда шатун
отошёл от последнего экстремума на `TURN_HYST_MM`; время и положение разворота
— в самом экстремуме. Оборот — НМТ→ВМТ→НМТ. Скачок положения больше 5 мм между
соседними записями (линейка прошла референтную точку) сбрасывает отслеживание.

**Стабильность оборотов.** Шаг испытания заканчивается, когда
`COLLECT_STABLE_CYCLES` последних оборотов подряд совпали по отбою и сжатию в
пределах `COLLECT_STABLE_PCT` % (но не меньше `COLLECT_STABLE_MIN_KGF` кгс).
Если за `COLLECT_MAX_CYCLES` оборотов не совпали, в результат идёт оборот с
наибольшим усилием (отбой + сжатие), в лог — WARNING с пиками всех оборотов.
Оператору это не показывается.

## Аварии

`AlarmSteps` (`scripts/controller/alarm_steps.py`). Любая авария прекращает
испытание, закрывает запись в архиве (прерванное температурное сохраняется с
накопленными точками) и включает красную лампу.

| Авария | Источник | Реакция |
|---|---|---|
| потеря управления | бит 3 `0x2003` (контроллер блокирует привод, если команд нет 1 с) | стоп приводов |
| превышение усилия | бит 4 `0x2003` (порог — аварийное усилие, пишется при старте) | стоп приводов |
| ограждение | бит 8 `0x2003` | стоп приводов |
| перегрев | температура ≥ максимальной для амортизатора (кроме температурного испытания) | стоп и доводка до НМТ |
| концевик траверсы | `0x2005`, аварийные верхний/нижний | стоп приводов, сообщение с кнопкой «ОПУСТИТЬ»/«ПОДНЯТЬ» |
| нет данных буфера | страховка буфера | стоп приводов |

Фильтр помех: ограждение и перегрев засчитываются, только если сигнал держится
`ALARM_FILTER_READS` чтений и `ALARM_FILTER_MS` мс; концевики траверсы —
`TRAVERSE_ALARM_MS` мс (настоящий концевик держит сигнал до действий
оператора). Короче — WARNING «… и пропал - помеха» с длительностью и, для
траверсы, какой концевик и где стояла траверса. Потеря управления и превышение
усилия не фильтруются — их фиксирует контроллер. Концевики траверсы читаются
только при чтении регистров (между этапами), в буфере их нет.
«Макс температура» испытания — по медиане трёх последних чтений.

## Жёлтая кнопка

Кнопка SB3 на стенде (бит 13 `0x2003`), `scripts/yellow_button.py`: одно
нажатие — одно событие (защита от дребезга 0.1 с, пауза 1.5 с между
срабатываниями), читается и из регистров, и из буфера. Уровень «отпущено»
определяется для каждого источника (в одной из прошивок кнопка была
инвертирована — тогда WARNING `бит 13 ... инвертирован`).

Нажатие = активная экранная кнопка (`AppWindow.yellow_btn_pressed`):
«ЗАПУСК» в ожидании запуска, «ПРЕРВАТЬ ИСПЫТАНИЕ» во время испытания, «НАЗАД»
после испытания; в остальных состояниях — ничего.

## Расчёт результатов и графики

Для собранного оборота (`Model._pars_result_avarage_cycles` и далее):
- перемещение сдвигается так, что НМТ = 0;
- знак усилия переворачивается (отбой +, сжатие −);
- усилие × `FORCE_KOEF` + ноль датчика (обнуление в окне отладки или при поиске
  референтной точки);
- отбой / сжатие = |max / min усилия + выталкивающая сила| — статическая
  (вводится оператором) или динамическая (по усилию в НМТ и ВМТ);
- мощность — работа за оборот ∑|Δx|·|F| (кДж);
- частота качания f = v / (π · ход);
- контроль скорости: фактическая = π · ход / период оборота (INFO в логе для
  каждого шага, WARNING — если не набрана).

Конвейерное: `result_conveyor_test` сравнивает отбой/сжатие с допусками
амортизатора; индикатор в окне — по своей скорости, лампа стенда — общий итог
(красная, если хоть одна скорость вне допусков); лампа горит до «НАЗАД» / «Стоп».
Биты ламп и буфера в слове `0x2003` берутся из последней отправленной команды
(`Model.commanded_bits`), остальные — из прочитанного состояния.

Датчик силы в части записей буфера отдаёт −100000 (нет свежего значения) —
такие точки заменяются предыдущим значением (`ParserSPG023MK._replace_invalid_force`).

Графики (`scripts/calc_graph/`):

| Файл | График |
|---|---|
| `test_graph.py` | во время испытания: усилие/перемещение, сравнение скоростей, температурное |
| `move_graph.py` | архив: усилие/перемещение + цифры (отбой, сжатие, мощность, частота) |
| `boost_graph_one.py` | архив: усилие от модуля скорости (диаграмма Лампе №1) |
| `boost_graph_two.py` | архив: усилие от скорости со знаком |
| `triple_graph.py` | архив: ход, скорость и усилие по углу кривошипа (две оси) |
| `cascad_graph.py` | архив: отбой/сжатие от скорости по шагам каскада с допусками |
| `temper_graph.py` | архив: отбой/сжатие от температуры |
| `compare_graph.py` | архив: наложение выбранных испытаний |

Графики усилия (кроме тройного) рисуются с выталкивающей силой — пик совпадает
с цифрой отбоя/сжатия. В архиве усилие хранится без неё (она — отдельным
полем), сдвиг делается при отрисовке. Скорость на графиках — приращение
перемещения, сглаженное окном Ханна по замкнутому обороту.

## Modbus-протокол

RTU, `device_id=1`. Все адреса — именованные константы в
`scripts/modbus/registers.py`, биты — в `ParserSPG023MK`.

| Адрес | Содержимое |
|---|---|
| `0x2000–01` | усилие (float, старшее слово первым) |
| `0x2002` | перемещение штока (знаковое, ×0.1 мм; в программе ×(−0.1)) |
| `0x2003` | слово состояния: 0 буфер вкл, 1/2 красная/зелёная лампа, 3 потеря управления, 4 превышение усилия, 6 канал температуры, 8 ограждение, 9 блокировка траверсы, 11 ЧП занят, 12 датчик силы занят, 13 жёлтая кнопка |
| `0x2004` | счётчик времени, мс |
| `0x2005` | входы модуля МВ110-224.16ДН: концевики и блокировки траверсы |
| `0x2006` | положение траверсы (×(−0.05) мм) |
| `0x2007–08` | температура 1 (float) |
| `0x200A–0B` | аварийное усилие (float, запись перед испытанием) |
| `0x200C–0D` | температура 2 (float) |
| `0x2060` / `0x2061…` | длина и кадр команды для ЧП (контроллер ретранслирует) |
| `0x4000…` | буфер: 3000 записей × 6 регистров — номер записи, усилие (2), перемещение, слово состояния, температура ×100 |

## Справочники и профили каскада

Справочники амортизаторов (`amorts.ini`) и операторов (`operators.ini`)
редактируются из окон программы и лежат рядом с exe.

Профили каскада (`cascade.ini`, рядом с exe) правятся в текстовом редакторе;
кнопки «Профиль 1..4» на странице спецификации заполняют таблицу скоростей:

```ini
[Profile1]
name = Профиль 1
speeds = 0.05; 0.1; 0.15; 0.2; 0.25; 0.3
```

`name` — подпись кнопки, `speeds` — скорости в м/с через `;`, не больше 30.
Комментарии — только отдельной строкой. Файл перечитывается при каждом
нажатии. Скорости вне диапазона для хода амортизатора пропускаются с
предупреждением; скорости должны строго возрастать (проверяется при ручном
вводе, при загрузке профиля и перед стартом). При смене амортизатора таблица
перепроверяется: профиль перезаполняется под новый ход, из ручной таблицы
удаляются недопустимые скорости. Если `cascade.ini` нет, он создаётся из
`CascadeProfiles.DEFAULT_CONTENT`.

Серийный номер на конвейерном испытании после «НАЗАД» остаётся прежним
(автоувеличение отключено: номера бывают с буквами).

## Запуск

Окружение — [uv](https://docs.astral.sh/uv/): зависимости в `pyproject.toml`,
версии в `uv.lock`, Python 3.11 в `.python-version`.

```powershell
uv sync                    # .venv и зависимости (вместе с dev-группой)
copy .env.example .env     # при первом запуске, затем поправить COM-порт
uv run main.py
```

Нужен стенд на указанном COM-порту либо эмулятор; без подключения программа
стартует с сообщением «Нет подключения к контроллеру». Программа запускается
в одном экземпляре (`tendo.singleton`).

### Работа без стенда (эмулятор)

1. Пара виртуальных COM-портов через com0com, например COM3 ↔ COM4.
2. Modbus Slave с проектом из `MBSlave/` (регистры с `0x2000`, буфер с
   `0x4000`) на одном порту пары: RTU, 460800 8N1, Slave ID 1.
3. В `.env` — второй порт пары и `TIMEOUT = 0.1` (эмулятор отвечает за
   30–50 мс; с `0.02` ответов не будет).

## Сборка exe

PyInstaller — в dev-группе.

```powershell
.\build.ps1                 # основная программа  -> dist/SPG-023MK/
.\build_archive_view.ps1    # просмотр архива     -> dist/SPG-023MK Archive view/
```

- `build.ps1` — сборка (onedir, без консоли, иконка `icon/shock-absorber.ico`)
  и рядом с exe содержимое `dist/add` (справочники, `icon/`, `archive/`) и

  -DataDirs -OneFile -Console -Clean -Force`.

## Архив

`archive/ГГГГ-ММ-ДД.csv` — испытания за день (в окне архива дата ДД.ММ.ГГГГ).
Windows-1251, разделитель `;`, десятичная запятая — открывается в Excel.

- Запись — 2 строки: шапка (время, оператор, тип, амортизатор, серийник,
  параметры и допуски, выталкивающая сила, макс. температура, скорость) +
  первая координата (перемещение или температура), затем строка `*` + вторая
  (усилие или «отбой|сжатие» для температурного). Испытание закрывается строкой
  `end_test`. Каждая скорость лабораторного/конвейерного испытания и каждый шаг
  каскада — отдельная запись.
- Запись в файл (`WriterArch`) — фоновый поток с очередью. Если файл открыт в
  Excel, запись ждёт (просьба закрыть файл в статусбаре); при закрытии
  программы очередь дописывается; незакрытое прошлое испытание закрывается
  `end_test` при старте нового; `;` в текстовых полях заменяется на `,`.
- Чтение — `scripts/archive.py` (`ReadArchive`) в pydantic-схемы
  `LabSchema` / `ConvSchema` / `TempSchema` / `CascSchema`; понимает и
  UTF-8, и старые имена файлов ДД.ММ.ГГГГ.csv.
- Окно архива — `app/wins/archive_win.py`, общее для программы и
  просмотрщика: графики, сравнение испытаний, скриншоты.

**Правка архива в Excel** возможна, программа такой файл прочитает, но Excel
переделывает значения во всём файле:
1. Сохранять как «CSV (разделители — запятые)», не в .xlsx.
2. Серийники, похожие на даты или числа (`1-2`, `1/2`, `007`), Excel портит —
   открывать через «Данные → Из текста/CSV» с текстовым типом этих колонок.
3. В Excel не больше 16 384 колонок: на малых скоростях и больших ходах
   оборот бывает длиннее. Если Excel предупреждает, что файл загружен не
   полностью, — не сохранять.
4. Править между испытаниями: пока файл открыт, программа не может в него писать.

## Логи и диагностика

- `logs/ГГГГ-ММ-ДД.log` — лог программы (уровень `LOG_LEVEL`). Полезные строки:
  - `Stage A -> B` — переходы этапов (DEBUG);
  - `Скорость испытания: задана …, фактически … (±… %)` (INFO);
  - `Шатун остановился через N с после команды «стоп», положение …` (INFO);
  - `Обороты шага совпали за N` (INFO) / `Обороты шага нестабильны …` (WARNING);
  - `… сигнал аварии … и пропал - помеха` (WARNING);
  - `Траверса проехала цель …` / `возврат к цели` (WARNING);
  - `Страховка буфера: …` (WARNING);
  - `Настройка хода: шатун остановился на …, отклонение …` (DEBUG);
  - `Скачок координаты линейки …` (DEBUG) — линейка прошла референтную точку.
- **Запись буфера** (`BUFFER_DUMP = 1`, `scripts/buffer_dump.py`): сырой поток
  буфера и события обмена (команды и подтверждения, бит «буфер включён», этапы,
  команды ЧП, события коллектора, аварии) в
  `logs/buffer/ГГГГ-ММ-ДД/ЧЧ-ММ-СС_<операция>.csv`, файл на операцию стенда,
  2–4 МБ на испытание. Файлы не удаляются — включать на время разбора.
  Разбор (`tools/buffer_dump/`, запуск из корня проекта):
  - `analyze.py ПАПКА|ФАЙЛ [-v] [--csv DIR]` — задержки включения буфера,
    старые записи, разрывы, скачки, этапы и события;
  - `replay.py ПАПКА|ФАЙЛ` — прогон записи через `CycleCollector` (цели доводки до НМТ);
  - `check_turns.py ПАПКА|ФАЙЛ [--hyst 1.0]` — проверка определения разворотов
    (двойные и укороченные обороты).
